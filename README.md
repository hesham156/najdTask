# najdTask — نظام إدارة أوردرات المطبعة

نظام متابعة أوردرات مطبعة بلوحة كانبان بالسحب والإفلات، بالعربية بالكامل (RTL)،
مع نظام أدوار وصلاحيات دقيق، ويعمل كتطبيق موبايل قابل للتثبيت (PWA).

---

## الفكرة الأساسية

الأوردر الواحد قد يحتوي على أكثر من نوع شغل في نفس الوقت — أوفست وديجيتال واندور.
لذلك النظام يفصل بين مستويين:

| المستوى | المقصود | أين يظهر |
|---|---|---|
| **الأوردر** | الطلب ككل: العميل، الملفات، الفاتورة | أعمدة: الأوردرات ← التصميم ← الاكتمال ← المراجعة ← الفاتورة |
| **بند الشغل** | قطعة شغل واحدة بنوع إنتاج محدد | عمود نوعه: ديجيتال / أوفست / اندور |

بعد التصميم، الأوردر "ينفتح" إلى بنوده، وكل بند يصبح كارتًا مستقلًا في عمود نوعه.
**عامل الأوفست يرى بنود الأوفست فقط** — حتى داخل أوردر فيه شغل ديجيتال واندور.
ولما تنتهي كل البنود، كارت الأوردر ينتقل تلقائيًا إلى عمود الاكتمال.

## أعمدة اللوحة

```
الأوردرات → التصميم → ┌ الديجيتال ┐
                      ├ الأوفست   ├ → الاكتمال → المراجعة → الفاتورة وسند التسليم
                      └ الاندور   ┘
```

## التشغيل محليًا

المشروع مضبوط على **PostgreSQL** لأنه هدف النشر. عندك طريقتان:

**أ) على قاعدة Railway نفسها** (الأسهل) — انسخ `DATABASE_URL` العام من خدمة
Postgres في Railway وحطّه في `.env`:

```bash
npm install
cp .env.example .env      # ثم حرّر DATABASE_URL و AUTH_SECRET
npx prisma migrate deploy
SEED_DEMO=true npm run db:seed
npm run dev
```

**ب) على SQLite بدون أي سيرفر:**

```bash
npm install
npm run db:use-sqlite     # يبدّل المحرك
# اضبط DATABASE_URL="file:./dev.db" في .env
npx prisma db push
SEED_DEMO=true npm run db:seed
npm run dev
```

> ⚠️ لو اخترت (ب) فلا تعمل commit لملف `prisma/schema.prisma` بعد التبديل —
> Railway يحتاجه على `postgresql`. رجّعه بـ `npm run db:use-postgres`.

افتح <http://localhost:3000> وسجّل الدخول بـ `admin` / `admin123`.

### حسابات تجريبية

تُنشأ فقط عند `SEED_DEMO=true` — لا تُنشأ على الإنتاج.

| المستخدم | كلمة المرور | الدور | يشوف إيه |
|---|---|---|---|
| `admin` | `admin123` | مدير النظام | كل شيء |

| `digital` | `123456` | عامل ديجيتال | **عمود الديجيتال فقط** |
| `indoor` | `123456` | عامل اندور | **عمود الاندور فقط** |

## الصلاحيات

لكل دور ثلاثة أبعاد يضبطها الأدمن من شاشة **الأدوار والصلاحيات**:

1. **الأفعال** — يضيف / يعدّل / يشوف / ينقل / يحذف، لكل قسم على حدة.
2. **الأعمدة المرئية** — أي أعمدة تظهر له في اللوحة أصلًا.
3. **أنواع الإنتاج** — أوفست فقط؟ ديجيتال فقط؟ هذا ما يفصل عمال الإنتاج عن بعض.

كل الفحوصات تُطبَّق على **السيرفر** داخل كل مسار API — الواجهة تخفي الأزرار
كتحسين لتجربة الاستخدام فقط. البيانات غير المصرح بها لا تصل إلى جهاز المستخدم:

- `GET /api/board` لا يُرجع إلا الأعمدة والبنود المسموح بها.
- `GET /api/orders/[id]` يحذف البنود خارج نطاق المستخدم ويكتفي بإبلاغه بعددها.
- ملفات البنود لا يفتحها إلا من يرى نوع إنتاج البند.

دور **مدير النظام** لا يمكن تقييده — حماية من قفل النظام على الجميع بالخطأ.

## ترقيم الأوردرات

من **الإعدادات** تحدد رقم البداية وبادئة اختيارية (مثل `NJ-`)، وكل أوردر جديد
يأخذ الرقم التالي تلقائيًا. الحجز يتم بعملية زيادة ذرّية في قاعدة البيانات، فلا
يمكن لموظفَين متزامنَين الحصول على نفس الرقم. لا يُسمح بضبط رقم بداية أقل من أو
يساوي رقم آخر أوردر موجود.

| الطبقة | الاختيار |

| قاعدة البيانات | Prisma + PostgreSQL (والمخطط يعمل على SQLite كذلك) |

### ملفات يُرجَّح أن تحتاج تعديلها

- `src/lib/stages.ts` — الأعمدة وأنواع الإنتاج والمراحل. لإضافة نوع إنتاج جديد
  (مثل "ليزر") أضِف مفتاحه هنا وعمودًا مقابلًا، وباقي النظام يتكيّف.
- `src/lib/permissions.ts` — قائمة الصلاحيات.
- `prisma/seed.ts` — الأدوار الافتراضية.

## النشر على Railway

المشروع فيه [`railway.json`](railway.json) جاهز. الخطوات:

### 1. أنشئ المشروع والخدمات

- **New Project ← Deploy from GitHub repo** واختر `najdTask`.
- داخل نفس المشروع: **New ← Database ← Add PostgreSQL**.

### 2. اضبط متغيرات البيئة في خدمة التطبيق

| المتغير | القيمة |
|---|---|
| `DATABASE_URL` | `${{ Postgres.DATABASE_URL }}` ← اكتبها بالضبط كده، Railway بيحلّها لوحده |
| `AUTH_SECRET` | مفتاح عشوائي طويل (طريقة توليده تحت) |
| `ADMIN_PASSWORD` | كلمة مرور قوية لحساب `admin` |
| `UPLOAD_DIR` | `/data/uploads` |
| `MAX_UPLOAD_MB` | `50` |

توليد `AUTH_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

> لا تضبط `SEED_DEMO` على الإنتاج — لو ضبطتها `true` هتتعمل حسابات بكلمة مرور
> `123456` وأوردرات وهمية.

### 3. أضف Volume للمرفقات ← خطوة إجبارية

في خدمة التطبيق: **Settings ← Volumes ← New Volume**، ومسار التوصيل `/data`.

بدون الـ Volume كل الملفات المرفوعة **هتضيع مع كل إعادة نشر**، لأن قرص الحاوية
مؤقت. الـ `UPLOAD_DIR=/data/uploads` بيخلي المرفقات على القرص الدائم.

### 4. انشر

Railway هينفّذ تلقائيًا:

```
npm run build
npm run start:railway   →   prisma migrate deploy && tsx prisma/seed.ts && next start
```

يعني كل نشر: يطبّق أي migrations جديدة، يتأكد إن الأدوار وحساب admin موجودين،
ثم يشغّل التطبيق. الـ seed **لا يعدّل** أي دور موجود، فتخصيصاتك للصلاحيات لا
تُمسح عند إعادة النشر.

الفحص الصحي على `/api/health` — بيختبر الاتصال بقاعدة البيانات فعليًا، فلو
`DATABASE_URL` غلط هيفشل النشر بوضوح بدل ما يطلع تطبيق مكسور.

### 5. بعد أول نشر

- ادخل بـ `admin` وكلمة المرور اللي حطيتها في `ADMIN_PASSWORD`.
- من **الإعدادات** اضبط اسم المطبعة ورقم بداية الأوردرات.
- من **الأدوار والصلاحيات** ظبّط الأدوار على فريقك.
- من **المستخدمون** أضف الموظفين.

### تغيير الـ schema لاحقًا

```bash
# بعد تعديل prisma/schema.prisma
npx prisma migrate dev --name وصف_التغيير
git add prisma/migrations && git commit && git push
```

Railway هيطبّق الـ migration الجديد تلقائيًا في النشر التالي.
